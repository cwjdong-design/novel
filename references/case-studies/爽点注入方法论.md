## 第一部分：诊断信号与五项检查

读者反馈「不爽」「憋屈」「无感」→ 检查 5 项：

### 1. 钱是数字还是武器？
- ❌ 系统结算 → 看一眼 → 心里算账 → 继续干活
- ✅ 系统结算 → 立刻花出去 → 配角震惊 → 问题解决

### 2. 有没有「他们不懂」的神秘感？
- ❌ MC 解释「我在穗城做过六年水产」
- ✅ MC 展示异常能力 → 配角愣住 → MC 不解释

### 3. 有没有打脸节奏？（每章至少一次）
- 被质疑/被看低 → 展示实力 → 对方闭嘴
- 对象可变：渔民、阿坤手下、海昌来人、甚至家人

### 4. 有没有收入对比？
- 锚点：渔民日入 300、女工月薪 1800、系统日结 15000
- 不强制每章，但不超过两章不出现

### 5. 系统是金手指还是计算器？
- ❌ 系统只提供数字，MC 靠自己奋斗
- ✅ 系统是 MC 的秘密武器，配角无法理解来源

## 第四部分：爽点追回实例（Ch16-24）

> 来源：2026-07-27 深度审查。

### 诊断
9 章（Ch16-24）布局期，仅 Ch20 章末有金句级钩子，零章达 ≥3 爽点标准。

### 追回执行（4轮）
1. 文档修复（delegate_task）: 伏笔表/系统状态/人物总表
2. 字数补全（Claude Code CLI opus）: Ch23 1424→2238, Ch24 1720→2413
3. 爽点注入（Claude Code CLI opus）: Ch16 数据对比/Ch17 被动标记/Ch20 算成本/Ch21 三张牌

- 连续3章零爽点=读者开始弃

- 系统被动数据对比是最安全的爽点
- 追回比预防贵4倍:PREP阶段就应规划爽点密度

## 第五部分：爽点追回技法库 — v1.0

> 深度审查后发现连续多章爽点断崖时的小手术技法。不重写整章，150-400字微型注入。

### 触发条件

审查报告发现连续 ≥3 章满足以下 ≥2 项：
- 零打脸场景
- 零金色结算
- 零震惊反应 / 收入对比
- 章末无钩子（广告打断点失效）
- 处于「布局期」（主角在收集信息/制定计划阶段）

### 技法1：系统被动数据标记

**场景**：信息章，读者大量吸收情报但感受不到系统存在。

**做法**：章末系统面板附近插入一行灰色小字，做被动数据对比。只报数，不判断好坏。不增加面板永久维度。

**模板**：
```
他正要关屏幕，面板底部又浮上来一行灰色的字。不是提示，不是警告——就是几个数字，冷冰冰地并排排着。

海安码头日均收虾一百七。穗城宏远水产日均收虾八百六。收购价差百分之十二。

林越看了三秒。然后把屏幕按灭。
```

**注入规格**：~80-120字。章末面板之后、角色关屏之前。

**实战**：Ch16 章末注入数据对比（170 vs 860）。

---

### 技法2：算三张牌

**场景**：主角出发面对强敌前，读者需要「主角有底牌」的安全感。

**做法**：主角在方向盘前/独处时，内心过一遍自己的底牌。每张牌 ≤1句话。最后一张是对方看不到的（系统的被动日结），制造不对称信息优势。

**模板**：
```
林越在方向盘前过了一遍——

码头十七条船，每天一百七十斤虾。老周、阿辉、刘芳——底座在。

冷库沈知予。仓储优先权加穗城冷库圈的人脉。冯志强不知道她的存在。

十六万现金，加每天一万六的日结。被动收入——冯志强没有这个东西。

他算完，把三张牌在心里翻了一遍。对方牌面大，但对方的牌他都看到了。而他的第三张牌，冯志强看不到。
```

**注入规格**：~300-400字。章末1/3处或场景转场。

**实战**：Ch21 林越出发穗城前算牌。

---

### 技法3：「被抽走」数字

**场景**：角色讨论对手时，信息停留在「对手很强」层面，缺乏情感冲击。

**做法**：另一角色快速心算——不是对手赚多少，而是自己被抽走多少。用具体损失数字制造危机感。

**模板**：
```
沈知予没说话。她在手机上敲了几个数，把屏幕转给林越看。

「你知唔知海安一天被抽走几多？」

屏幕上的数字不大，但每一个都是用计算器敲了三遍的——穗城往海安方向的反向收购量，折合成海安的日产量损耗，百分比，趋势线。

林越看了一眼。百分比是两位数。
```

**注入规格**：~150-200字。信息讨论场景的收尾处。

**实战**：Ch17 德兴楼场景扩展。

---

### 技法4：新视角看老码头

**场景**：人情章/过渡章，缺乏外部冲突但需要让读者重新感受主角成就。

**做法**：通过新登场角色的眼睛重新展示已有场景。不说「林越很厉害」，而说变化的数据。

**模板**：
```
周海生跟在老周后面走了一段。码头上每条船他都认得——有些换了新发动机，有些补了新漆。以前只有四条船的时候，每条船几点来几点走，他闭着眼都能背出来。现在多了，记不住了。

一个渔民从过秤那边走过来，手里攥着四张红票子，边走边往兜里塞。周海生看了一眼。以前的码头，阿坤给两张半。
```

**注入规格**：~200-300字。新角色出场后的第一段码头描写。

**实战**：Ch23 周海生视角扩充 + 盯梢三人B线（技法5）。

---

### 技法5：B线平行注入（纯人情章救场）

**场景**：纯人情/铺垫章，缺乏外部冲突，读者说「想弃」。

**做法**：不删原有情感戏。注入一条独立B线——已有角色的新视角（如对手方的盯梢人），章首/中段/章末共3处剪入。B线延续主线张力，A线不被破坏。

**注入规格**：~800字（章首200+中段300+章末300）。三人视角交替。

**实战**：Ch23 注入三个宏远盯梢人的视角——章首「照实讲」、中段「连佢都返」、章末「冇异常」「继续睇」。人情+压迫感双线，字数从2238→3178。

---

### 技法6：角色弧线追回（多节点微型注入）

**场景**：配角（如女主）在全书早期出场多次但始终是功能角色——没有独立欲望/困境/决策。

**做法**：选取3个关键出场节点，各注入100-150字她的独立瞬间。不是加一场大戏，而是埋线——让读者回头看时发现她一直在。

**三个节点的选择**：
1. 首次出场后 — 她的日常生活：家人在医院、她每天经过但不停
2. 关键决策场景 — 她签合同/谈条件时，一秒钟的私人记忆闪过
3. 送主角出发时 — 她独处时刻：黑暗冷库里握着属于自己的东西

**关键原则**：不帮她帮林越，不写她对林越的感情。写她自己的困境。

**注入规格**：每个节点100-150字。3个节点共~400字。

**实战**：Ch4/12/21 沈知予三节点——Ch4骑车经过父亲病房不停、Ch12窗外病号服老人让她停了一秒、Ch21黑暗冷库里拿出三个电话号码和冻虾。

## 第六部分：注入 SOP

1. 备份原章
2. 准备 prompt 文件（避免 shell 中文引号炸），写入完整原文 + 插入指令
3. `claude --model sonnet --max-turns 12-15 --dangerously-skip-permissions -p "$(cat /tmp/prompt.txt)" > /tmp/result.md`
4. 验证：`review_scan.py` → 字数 ≥2000 → 系统面板完整 → 零违禁
5. 存盘

### 常见坑

| 坑 | 症状 | 处理 |
|----|------|------|
| opus 只输出新增片段 | 输出文件 <500字节 | 提取片段后 `patch` 植入原文，不重跑 |
| prompt 太长 opus 15轮未完成 | `Error: Reached max turns (15)` | 简化 prompt，删除原文改为内联简要指令 |
| 新内容引入违禁地名 | review_scan 命中 | 发回 opus 重写（在 prompt 中重复铁律） |
