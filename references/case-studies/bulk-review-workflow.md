# 批量审查工作流（30章级全量审查）

> ⚠️ **特定书籍复盘文档**：以下内容来源于特定书籍的实战经验，其中的章节号、人物名、地名、数字均为该书的设定。方法论部分可通用参考，但具体数据不具有普适性。

> 来源：2026-07-27 1-30章全量审查实战
> 场景：需要对已修改后的多章（10-30章）做一次性全覆盖审查，产出逐章明细+汇总结论+对比原审查报告

## 触发条件

- 用户说「审查全部章节」「全部审查」「章章不落下」
- 多章修改后需要验证修复效果
- 系统修改/批量改写后需要全量回归

## 审查流程

### 步骤1：确定审查范围

- 明确起始章和结束章（如1-30）
- 确认是否有原审查报告做对比（如 GPT-5.5 深度审查报告）
- 确认是否已有当前正文（不是骨架，是最终版正文）

### 步骤2：编写审查脚本

审查脚本在 `execute_code` 中运行，覆盖以下检查项：

| 检查项 | 方法 | 说明 |
|--------|------|------|
| 字数统计 | 正则 `[\u4e00-\u9fff]` 计数 | 纯汉字，不含标点/标题/空行 |
| 爽点五项 | 关键词匹配 | 钱落地/震惊反应/打脸/收入对比/系统神秘化 |
| 系统术语违规 | 违禁词列表匹配 | 排除否定句/合法语境误报 |
| 真实地名违规 | 黑名单匹配 | 番禺/广州/湛江等32个 |
| AI禁用词 | 一级违禁词匹配 | 排除对话中引用 |
| 自动扫描 | 调用 `review_scan.py` | 获取一级命中数 |

## 常见误报处理

### 1. 系统术语误报场景

| 误报词 | 合法语境 | 判断方法 |
|--------|---------|---------|
| 新手礼包 | 「没有新手礼包」（否定句） | 前面20字内是否有「没有/不/没」 |
| 预警 | 「气象台的预警短信」（天气预报） | 是否是气象台/政府预警，非系统预警 |
| 建议 | 「没有任何建议」（强调系统克制） | 前面是否有「没有任何」 |

### 2. 地名白名单误报

`review_scan.py` 的正则 `([^\s]{1,3}(?:港|城|市|县|镇|村|岛|湾|塘|码头|市场|广场|大厦))` 会把：
- 「XX码头」中的「码头」——拆分后「码头」不在白名单 → 误报
- 「XX城」中的「城」——拆分后「城」不在白名单 → 误报

**判断方法**：人工确认完整地名是否在白名单中。白名单中的「码头」「穗城」「海安」「宏远水产」等是合法表述。

### 3. 真实地名沙盒

- 正文中**禁止**出现：番禺/黄埔/海珠/天河/越秀/荔湾/白云/南沙/花都/增城/从化/佛山/中山/东莞/珠海/深圳/惠州/江门/肇庆/广州/湛江/茂名/阳江/汕头/潮州/揭阳/珠江/南海/顺德
- 主角对话中提及「穗城」「海康」「海安」是合法的架空地名
- 粤语对话中出现的「穗城」是设定内的合法地名

## 速度基准

30章全量审查（含自动扫描调用）预计 5-10 秒完成，纯规则匹配，无LLM调用。

## 报告验收标准

- [ ] 逐章明细表：30章全部覆盖，无遗漏
- [ ] 字数统计精确（纯汉字，≥2000推荐，1700底线）
- [ ] 爽点五项每章逐一检查，统计覆盖率
- [ ] 真实地名、系统术语、AI禁用词分别统计
- [ ] 对比原审查报告：S/A/B级修复逐项验证
- [ ] 最终结论：合格/需修复，明确给出发布建议
