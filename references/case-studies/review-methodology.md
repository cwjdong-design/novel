## 第一部分：深度审查五步流程（2026-07-27 实战提炼）

```
自动扫描 → 跨文档一致性 → 逐章质量审读 → 爽点周期诊断 → 累积风险汇总
```

### 第一步：自动扫描

三工具并行运行：

| 工具 | 路径 | 扫描项 | 假阳性陷阱 |
|------|------|--------|-----------|
| `review_scan.py` | `~/.hermes/skills/novel/scripts/` | 系统术语/地名白名单/真实地名黑名单32词/AI禁用词/章末标记/标题格式 | ⚠️ 大量「地名白名单外」误报——拆分子串（如「沙水产市」来自「白沙水产市场」）。**人工复核时只看非「地名白名单外」的命中** |
| `novel_scan.py` | `~/.hermes/skills/novel/scripts/` | 违禁词库全面扫描（一级+二级） | 「建议」在「没有任何建议」语境中为假阳性。真实地名拆分（如「上海」来自「驶上海堤公路」）需人工判断 |
| `consistency_check.py` | `~/.hermes/skills/novel/scripts/` | 7维交叉校验 | 路径敏感——必须传 `--book "$(pwd)"` 完整路径 |

### 第二步：跨文档一致性

对照 7 个维护文档逐一检查更新状态：

| 文档 | 检查项 |
|------|--------|
| 人物总表 | 正文出现的人物是否注册 |
| 伏笔追踪表 | 已回收伏笔是否更新；是否有新伏笔未录入 |
| 系统状态 | 标题章节号是否最新；指标值是否与最新章面板一致 |
| 故事线状态 | 梗概是否覆盖到最新章 |
| 章节规划 | Ch25+ 标题和核心事件是否占位文本 |
| 前文时间线 | 最近3章梗概是否可读 |
| 分卷细纲 | 人物身份是否与正文一致 |

### 第三步：逐章质量审读

快速审读最近 5-10 章，每章关注：
- 章末钩子强度（是否制造了明确悬念/反转/新危机）
- 系统面板合规（固定三行+可选≤2行+纯被动数据）
- 字数底线（2000+，不含系统面板和章节标题）

### 第四步：爽点周期诊断

**这是单章审查无法发现的问题。** 需要跨章趋势分析：

| 区间 | 特征 | 风险 |
|------|------|------|
| Ch1-7 | 高频：金色结算/破格提示/打脸退场 | ✅ |
| Ch8-15 | 中频：海昌谈判/台风/金色结算 | ✅ |
| Ch16-24 | 低频：布局期，信息密但无兑现 | 🔴 |

**诊断方法**：统计连续章节中「钱落地/震惊反应/打脸/系统神秘化/收入对比」5项爽点的出现频率。若 ≥3 章零爽点 → 标记「布局期警告」。

**「布局期」定义**：连续多章以信息推进为主（揭底/调查/分析/计划），无直接冲突/打脸/金钱落地。番茄平台读者耐心=3章，布局期 > 5章 = 高风险。

### 第五步：累积风险

| 风险项 | 检查方法 |
|--------|---------|
| 伏笔超期 | `foreshadow_check.py` 检测 🔴近期 状态的伏笔 |
| 广告打断点 | 每 3/6/9 章章末是否为强钩子 |
| 读者审查周期 | 最近一次读者审查是否在 3 章内 |
| 金句储备 | 全书是否有 ≥5 句可截屏金句 |
| 字数漂移 | 最近 10 章是否有 ≥3 章低于 2000 |

## 第二部分：全量一致性审查清单（v2 — 2026-07-27）

> 来源：2026-07-25 第1-17章全量审查实战 + 2026-07-27 系统性修复实战
> 触发场景：完成一个大卷后 / 世界观变更后 / 发现不一致 bug 后 / 用户要求全量审查

### 审查方法（8步）

#### 1. 读取全部文件
- 正文分批并行读取（5章/批，分4批覆盖20章内）
- 设定文档并行读取：世界观、主线大纲、章节规划、全部人物卡、故事总纲、故事线状态
- 约需10-15个 read_file 调用

#### 2. 关键字搜索（8项）
每个关键字独立 search_files，并行发出：

| # | 搜索目标 | 关键词 |
|:--:|---------|-------|
| S1 | 废弃地名 | `珠河`（正文中作城市/地点用）|
| S2 | 禁止地理名 | `海康半岛`, `珠河入海口`(旧名) |
| S3 | 废弃冷库名 | `海康冷库` |
| S4 | 现实地名 | `珠江`, `广州`, `深圳`, `湛江`, `珠海`, `雷州`, `珠三角` |
| S5 | 现实车牌 | `粤A`, `粤B`, `粤C` |
| S6 | 禁止系统术语 | `投放回收比`, `宿主`, `检测到`, `解锁`, `阶段`, `动态上浮` |
| S7 | AI禁用词 | `或许\|仿佛\|然而\|于是\|顷刻间\|悄然\|似乎\|一丝\|泛起\|充斥\|勾勒\|雕琢\|绽放\|氤氲\|缱绻\|旖旎\|斑驳\|婆娑\|呢喃` |
| S8 | 白名单校验 | `穗A`, `海A`, `海B`(确认合法) |

#### 3. 分卷细纲漂移检测（v2 新增，与 S1-S8 并行）

> ⚠️ 2026-07-27 发现：第一卷分卷细纲只写到第10章且事件与正文完全不同；第二卷细纲中沈知予被写成质检员而非冷库技术主管——根本性角色定位错误。这些漂移会让 DRAFT prompt 注入错误上下文。

| # | 比对项 | 方法 |
|:--:|-------|------|
| D1 | 分卷细纲 vs 章节规划（实际） | 逐章对比核心事件，标记不一致 |
| D2 | 分卷细纲 vs 人物卡 | 检查角色定位（职业/身份/出场时间）是否一致 |
| D3 | 故事总纲 vs 分卷细纲 | 卷内章数、卷核心冲突是否连贯 |
| D4 | 故事线状态 vs 实际正文 | 检查章节梗概是否缺失 |

**修复策略**：以**正文和人物卡**为权威源重写分卷细纲，不修正文适配过时细纲。

#### 4-6. 人工扫描 → 人物卡对比 → 大纲对齐

#### 7. 分级：🔴必须修 / 🟡建议修

#### 8. 输出报告至 `审查报告_YYYYMMDD.md`

### 自动化扫描工具链

| 工具 | 路径 | 用途 | 触发时机 |
|------|------|------|---------|
| review_scan.py | `~/.hermes/skills/novel/scripts/` | 系统术语+地名+AI禁用词+对话框式 | 每章DRAFT后 |
| consistency_check.py | `~/.hermes/skills/novel/scripts/` | 7维跨文档交叉校验 | 每5章REVIEW时 |
| novel_scan.py | `~/.hermes/skills/novel/scripts/` | 违禁词库全面扫描 | cron / 手动 |
| foreshadow_check.py | `~/.hermes/skills/novel/scripts/` | 伏笔超期检测 | cron |

#### consistency_check.py 七维校验
- C1: 人物卡 ↔ 人物总表双向一致性（名称归一化）
- C2: 章节规划 ↔ 正文存稿章数/标题一致性
- C3: 故事线状态覆盖所有正文章节
- C4: 前文时间线速查覆盖最近3章
- C5: 伏笔表引用有效章节号 + 超期检测
- C6: 正文出场人物 → 人物库注册核查（含停用词过滤+简称匹配）
- C7: 大纲分卷章数总和 vs 故事总纲总章数

#### review_scan.py 扫描项
- 🔴 系统违禁术语（投放回收比/宿主/检测到等22词）
- 🔴 地名白名单外检查（含白名单）
- 🔴 AI禁用词（19词，对话中降级为 🟡）
- 🔴 对话框式字符（╔══╗）

## 第三部分：深度审查工具陷阱

> 2026-07-27 深度审查实战记录。纳入 novel-review 执行规范。

### review_scan.py 白名单误报

扫描器按子串匹配，白名单地名在特定上下文中会被误拆分：
- 「斤，穗城」「那片新塘」→ 匹配失败但实际无问题
- 判断标准：「穗城/海安/海康/珠河」→ 人工确认白名单内即通过
- 「X塘」类 → 检查是地点名（报）还是普通名词（跳过）
- Ch22-24 实测：28 命中全部误报，零实际违禁

### consistency_check.py 路径要求

必须传绝对路径，不能用相对路径：
```bash
# 正确
python3 ~/.hermes/skills/novel/scripts/consistency_check.py --book "$(pwd)"

# 错误
python3 ~/.hermes/skills/novel/scripts/consistency_check.py --book .
```

### novel_scan.py 参数

`--chapters N` 是整数（最近 N 章），不是逗号分隔列表：
```bash
# 正确: 扫描最近3章
python3 ~/.hermes/skills/novel/scripts/novel_scan.py --book "书名" --chapters 3

# 错误
python3 ~/.hermes/skills/novel/scripts/novel_scan.py --book "书名" --chapters "22,23,24"
```

### 跨文档同步滞后检测

深度审查时必须检查以下四项与最新章号是否匹配：
1. 系统状态.md 标题（如「截至 Ch.20」但最新 Ch.24）
2. 伏笔追踪表（已回收的伏笔是否仍标记为「远期」）
3. 故事线状态.md（最后一章梗概是否覆盖到最新章）
4. 人物总表.md（新出场人物的注册状态）

不匹配 = 一级阻塞，下一章开始前必须解决。

## 第四部分：修复策略与经验教训

### 文档类（delegate_task 派发）
- 伏笔表更新 / 系统状态更新 / 人物总表补注册
- 独立任务可并行派发

### 创作类（Claude Code CLI opus 派发）
- 补字数 / 爽点注入 / 章末钩子加强
- **铁律**：逐章派发，文件传参，输出验证
- prompt 格式：指定插入位置 + 铁律 + 原文全文 + "输出完整全文"
- **注意**：opus 有时只输出新增片段而非全文——需验证后手动 patch 或重新派发

### 爽点注入模式（三种可用模板）

1. **系统被动数据对比** — 系统弹出两个数字的冷冰冰对比（如海安170 vs 宏远860），不判断好坏。灰色小字。
2. **外部视角看钱** — 配角第一次看到主角的经济运作，通过配角的眼睛让「钱落地」被读者看见。
3. **算牌内心独白** — 主角在关键时刻过一遍自己的牌和对手的牌，制造战略爽感。

### 经验教训

- **review_scan.py 假阳性泛滥**：任何时候看扫描结果，先过滤掉「地名白名单外」分类。
- **opus 不总是输出全文**：补字数类 prompt 需强调"输出完整全文"，否则可能只输出新增片段。
- **1936 ≠ 2000**：opus 对字数指令的执行精度约 ±10%。差 64 字不再补——再跑一轮就是灌水。
- **Ch20 章末是金句不能碰**：扩展内容必须在章末之前插入，不能改写金句段落。
