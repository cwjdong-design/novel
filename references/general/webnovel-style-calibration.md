# 网文风格校准方法论

> 来源：2026-08-07 第一卷48章复盘。用户反馈：「你说的这些这么隐晦的表达，网文都是大白话，直接爽。」
>
> 核心问题：AI（Claude Code sonnet）默认产出的是"文学感网文"——冷、隐晦、克制、留白多。番茄读者要的是"大白话网文"——直接、爽快、情绪到位、一口气读完。这两者之间的差距不是"去AI味"能解决的（AI味已经很低了），而是**网文类型意识缺失**。

## 一、问题诊断：文学感网文 vs 大白话网文

| 维度 | 文学感网文（AI默认产出） | 大白话网文（读者要的） |
|------|----------------------|-------------------|
| 情绪表达 | 留白让读者自己体会 | 直接写出来，读者不用猜 |
| 打脸 | 对手「脸色铁青」「没说话」就完了 | 对手的震惊、不服、彻底服气要写透，围观者反应要给足 |
| MC形象 | 沉默寡言、深沉（读者觉得闷） | 话不多但每句到位，做事干净利落（读者觉得牛逼） |
| 信息密度 | 一章一个事件，慢慢推进 | 一章2-3个事件，信息量大但不乱 |
| 比喻 | 精巧隐晦（读者get不到） | 大白话或不用比喻 |
| 节奏 | 铺垫→推进→高潮→钩子（匀速） | 直接进冲突，中间不停，结尾炸 |
| 读者感受 | 「写得不错但不太想追」 | 「卧槽然后呢」 |

## 二、10条网文校准规则

### 1. 情绪直接给，不留白
- ❌ 「小陈脸色铁青。一个字没说，转身走了。」（读者：哦，走了）
- ✅ 「小陈脸一阵红一阵白。他张了张嘴想说什么，但留样就摆在那里。他低着头走了。旁边两个采购看着他背影，互相看了一眼。」（读者：爽）

### 2. 打脸要写透，不收太快
打脸是网文核心爽感。质疑→实力展示→对手反应→围观反应→结果，五步缺一不可。
- ❌ 质疑→展示→对手走了（三步就收）
- ✅ 质疑→展示→对手愣住→围观议论→对手找补→实力再碾压→对手彻底闭嘴→围观佩服→结果落地（九步打透）

### 3. 围观者反应是爽感放大器
MC做了牛逼的事，必须有旁观者给出"震惊""佩服""嫉妒""讨论"的反应。没有旁观者=没有爽感。
- ❌ 林越搞定三家酒楼，直接走了
- ✅ 林越搞定金海楼的消息传到第二家，第二家主动来找——这是"传出去"的爽感

### 4. MC台词短但每句都要有分量
短不等于闷。短意味着每句话都是判断/决定/行动指令，不是闲聊。
- ❌ 「嗯。」（读者：他在干嘛？）
- ✅ 「先去金海楼。」（读者：为什么先去最难的？好奇了）

### 5. 事件密度要高
网文一章不是写一个场景，是写2-3个场景，每个场景都有信息增量和情绪变化。
- ❌ 一章只写一个电话+一个汇报
- ✅ 一章写验虾打脸+消息传开+对手反应+船回来+面板弹——信息量大，读者一口气看完

### 6. 钱要看得见
系统流的核心爽感是"赚钱"。日收入、月收入、利润对比、对手亏多少——数字必须具体且频繁。
- ❌ 「收入增加了」（多少？）
- ✅ 「日收入从17815涨到18675。多了860块。」然后对比对手：宏远在海康每斤亏2块×每天2000斤=每天亏4000

### 7. 对手要蠢但不弱
对手太弱=没有爽感。对手很强但犯了错=MC赢了更爽。对手要在MC崛起的过程中有反应——不爽→打压→失败→不甘→服气/退场。
- ❌ 对手从头到尾只出现一次，打完就消失
- ✅ 对手的反应是分阶段的：先看不起→然后慌→然后反扑→然后认输

### 8. 每章结尾必须让读者想看下一章
不是"留白"——是"钩子"。钩子是具体的：谁来了？什么消息？什么危机？
- ❌ 「码头的一天结束了。」（读者：可以睡了）
- ✅ 「手机响了。一个没存过的号码。」（读者：谁？！）

### 9. 叙述语言用大白话
不写文学腔。用最直白的词把事情说清楚。读者12秒扫一段，文学比喻看不懂就跳过。
- ❌ 「面板浮在视野中央，像一张被揉皱的纸。」
- ✅ 「面板弹出来了。日收入：十万零七百。」

### 10. 系统面板要让人兴奋
面板不是记账本，是爽感来源。数字跳变、新维度解锁、金色字——每次面板出现都要让读者和MC一起"卧槽"。
- ❌ 面板弹出来，MC看一眼收掉
- ✅ 面板弹出来，MC盯着看——因为这个数字意味着他做到了某件不可能的事

## 三、REVIEW阶段附加：网文校准检查

在爽点5项+跨章衰减检查之后，追加以下校准扫描：

```
[ ] 情绪留白检查：本章有没有"脸色变了但读者不知道什么感受"的段落？→ 补围观反应或内心直给
[ ] 打脸完整度：如果有打脸场景，质疑→展示→反应→围观→结果五步是否齐全？→ 缺哪步补哪步
[ ] 事件密度：本章实际推进了几个事件？只有1个→退回PLOT加事件
[ ] 钩子强度：章末最后一句让读者"想知道下一章"吗？→ 如果是环境描写/状态描述→重写钩子
[ ] 叙述大白话检查：随机抽3段叙述，有没有文学比喻读者看不懂的？→ 改成大白话
[ ] 对手反应：对手在本章或前几章有没有给出足够的反应？→ 对手消失太久=爽感断裂
```

## 四、DRAFT prompt 追加注入

骨架模式 prompt 的3条铁律之外，追加网文校准片段：

```
【网文校准（必须遵循）】
- 情绪直接给读者，不留白。对手被打脸后的反应要写透（震惊/不服/闭嘴），围观者要有反应。
- 事件密度高：本章2-3个场景，每个场景都有信息增量和情绪变化。不要一章只写一件事。
- 大白话叙述。比喻读者看不懂就不用。数字要具体。
- 章末钩子要具体（谁来了/什么消息/什么危机），不要环境描写收尾。
- MC台词短但每句有分量（判断/决定/指令），不是"嗯""好"这种无信息回复。
```
