# 番茄网文写作节奏铁律

> 来自 2026-07-25 深度审查 + 15 章写作实战

## 平台核心认知

1. **番茄奖励「爽」不奖励「好」**。文笔加分，节奏基本盘。
2. **读者耐心 = 3 章**。3 章内无打脸 → 弃书。
3. **每章 ≥ 3 个爽点**。短剧观众 1 分钟一个反转。
4. **系统每 5 章至少一次「炸屏」**——金色字、新数据维度。
5. **主角主动出击**：不是事情发生在主角身上，是主角让事情发生。

## 爽点五项检查（每章必过）

- 钱落地：系统钱当场花出去 / 被配角看见
- 震惊反应：有人不理解 MC 资源 → MC 不解释
- 打脸节奏：被质疑 → 展示实力 → 对方闭嘴
- 收入对比：渔民 300 vs 系统 15000+（不超过两章不出现）
- 系统神秘化：配角察觉异常但无法理解来源

## 广告打断点

- 第 3/6/9 章章末必须是强钩子（信息截断/视角切换/倒计时型）
- 每 3 章至少一句可截屏金句

## 系统设计原则

- 系统从不主动说话，但数据本身有叙事力量
- 每 5 章加一个新数据维度（不是新功能，是新视角）
- 第一炸屏（Ch3）：暗金色破格提示，+15% 上浮
- 第二炸屏（Ch5）：结算跳 ¥23,845
- 第三炸屏（Ch7）：连续运营天数 + 累计结算
- 第四炸屏（Ch14）：首次红字扣款（必须达到日结算 50%+）
- 第五炸屏（Ch15）：金色台风通过，累计突破 ¥246,800

## 人物配置铁律

- 女性角色必须前 5 章出场
- 反派冲突前 3 章就要有摩擦
- 每个配角要有自己的 Want（不是口号）
- 章末作者互动 50-80 字（引导评论/投票/追读）

## 审查管道

1. PREP → novel-character（Want/Need 追踪）
2. PLOT → novel-platform（广告打断点规划）
3. DRAFT → Claude Code opus（逐章派发，不批量）
4. REVIEW → review_scan.py + 爽点 5 项 + 读者审查（每 3 章）
5. TRACK → novel-platform（章末读者互动模板）

## 常见节奏问题

- 前 4 章半无外部冲突 = 死刑。Ch1 系统激活 + 微冲突。
- 第 15 章不能像阶段性总结——必须有新钩子。
- 反派不能第 15 章就被打趴——需要反扑空间。
- 「数据汇报式」对话在番茄上等于划走信号。
- 关键对话中插入 1 个动作细节打破 AI 感。
