# 初始化新书（v2.0）

## 触发条件

用户说「新开一本书」「创建新书」「开始写《XXX》」「新建小说」时使用本技能。

## 执行流程

---

### 阶段 1：收集创作信息（引导式对话）

按照以下顺序，每次只问一个问题，根据回答自然推进。不要一口气列出所有问题。

#### Q1：书名确认

**话术**：
> 好的，我们来创建一本新书！首先确认一下，书名是什么？

如果用户已经说了书名（如「开始写《修仙从种田开始》」），则跳过此问，直接确认：
> 书名就用《修仙从种田开始》，对吗？

**输出**：书名（将用作目录名，将中文标点替换为对应字符，例如《》→无，空格→下划线）

#### Q2：一句话简介

**话术**：
> 棒！用一句话介绍这本书的核心卖点？想想你会在番茄小说封面上写什么——50 字以内，让读者一眼就想点进来。

**引导示例**：
- 「重生回到末世前 3 天，他带着未来 10 年记忆，这次要成为最强」
- 「系统要我当反派，但我只想种田变强」
- 「穿越成豪门假千金，全网黑的时候，真千金跪求我回家」

**输出**：一句话简介（≤50 字）

#### Q2.5：主角年龄

**话术**：
> 主角多大？这个很重要——番茄平台要求主角必须 ≥18 岁才能有恋爱线。

**输出**：主角年龄（≥18）

#### Q3：小说类型

**话术**：
> 选一下类型？常见的番茄热门类型有：
> - **都市**（重生、鉴宝、官场、商战）
> - **玄幻**（东方玄幻、高武）
> - **仙侠**（修真、修仙、洪荒）
> - **系统**（系统流、数据化、游戏化）
> - **末世**（丧尸、废土、生存）
> - **悬疑**（灵异、探案、密室）
> - **言情**（霸总、甜宠、虐恋）
> - **其他**——你可以自己描述

**输出**：类型标签（可以是组合，如「都市+系统」）

#### Q4：主角设定

**话术**：
> 聊聊主角～ 告诉我三件事：
> 1. **姓名**
> 2. **核心身份**（重生者？穿越者？普通人逆袭？）
> 3. **金手指/核心优势**（系统？记忆？特殊能力？）

如果是系统流，追问：
> 系统叫什么名字？主要功能是？

如果用户回答简略，引导补充：
> 顺便说说主角的性格？冷静型 / 热血型 / 腹黑型 / 咸鱼型？

**输出**：主角姓名 + 身份 + 金手指 + 性格

#### Q5：计划篇幅

**话术**：
> 计划写多长？
> - 【A】短篇冲量 — 20-30 万字，快速完结
> - 【B】中篇连载 — 50-80 万字，稳定更新
> - 【C】长篇小说 — 100 万字以上，长期规划
> - 【D】还没想好，先写着看

**输出**：篇幅级别（short/medium/long/flexible） + 估算字数

#### Q6：创作红线

**话术**：
> 最后，有没有绝对不能踩的红线？（为了让 AI 记住底线，避免写出你不想要的内容）

**引导示例**：
- 「不虐主」—— 主角不能被虐
- 「不后宫」—— 不搞多女主感情线
- 「不写死核心配角」—— 指定哪些角色不能死
- 「不写政治相关」—— 避免敏感内容
- 「主角必须低调」—— 不要过早暴露实力
- 「每章必须有爽点」

**输出**：红线列表（3-8 条）

### 阶段 2：创建目录结构

使用 `terminal` 工具执行以下命令族，一次性创建完整目录：

```bash
mkdir -p ~/novels/books/<书名>/{00-大纲细纲/分卷细纲,01-正文存稿,02-设定文档/人物库,03-版本备份,04-错误库}
```

同时在技能状态目录创建进度文件：
```bash
mkdir -p ~/.hermes/skills/novel/_state
```

**首次运行检查**：如果 `~/novels/_shared/logs/` 和 `~/novels/_shared/backups/` 不存在，自动创建：
```bash
mkdir -p ~/novels/_shared/{logs,backups}
```
这两个目录供 novel-cron 每日巡检写入日志和全局备份使用。所有脚本统一存放在 `~/.hermes/skills/novel/scripts/`（唯一权威位置），`~/novels/_shared/` 下**不再有 scripts 目录**（已去除软链接兼容层，2026-08-01 优化）。

**最终目录结构**：
```
~/novels/books/<书名>/
├── 00-大纲细纲/
│   ├── 主线大纲.md          # 自动生成
│   ├── 作品简介.md          # 自动生成
│   ├── 分卷细纲/             # 空，按需手工创建
│   └── 章节规划.md          # 自动生成
├── 01-正文存稿/              # 空
├── 02-设定文档/
│   ├── 书配置.md            # ⭐ 自动生成（该书专属规则）
│   ├── 世界观.md            # 自动生成
│   ├── 人物库/
│   │   └── 主角_<姓名>.md   # 自动生成
│   ├── 伏笔追踪表.md         # 自动生成
│   └── 故事线状态.md         # 自动生成
├── 03-版本备份/
│   └── 备份日志.md          # 自动生成
└── 04-错误库/
    └── 修正记录.md          # 自动生成

~/novels/_shared/              # 首次运行时自动创建
├── logs/                      # novel-cron 每日巡检日志
└── backups/                   # cron 每日全量备份
```

### 阶段 3.5：骨架完整性检查（硬性拦截）

在阶段 3（自动填充初始模板）完成后、用户说「开始写第 1 章」时，执行以下骨架检查。**任何一项未通过 → 拦截，不允许开始写作。**

#### 3.6.1 检查项

| # | 检查项 | 判定标准 | 拦截提示 |
|---|--------|---------|---------|
| 1 | **主角人物卡** | `02-设定文档/人物库/主角_<姓名>.md` 中存在，且「## 基本信息」「## 性格」「## 能力/金手指」三个核心段落均有实质内容（非「（请填写）」） | ❌ 主角人物卡未完成，请先填写基本信息、性格和能力设定 |
| 2 | **核心配角人物卡** | `02-设定文档/人物库/` 下至少存在 **3 张**配角人物卡（.md 文件），每张卡至少包含角色姓名、身份、与主角关系、基本性格 | ❌ 核心配角人物卡不足 3 张（当前：N 张），请先在 `02-设定文档/人物库/` 中创建至少 3 个配角 |
| 3 | **主线大纲** | `00-大纲细纲/主线大纲.md` 中「## 三幕结构」的每一幕均有 ≥ 1 行实质描述（非「（请填写）」） | ❌ 主线大纲未完成，请先填写三幕结构（每幕至少一句话） |
| 4 | **第一卷细纲** | `00-大纲细纲/分卷细纲/` 下存在第一卷的细纲文件（如 `01_第一卷.md`），且包含 ≥ 5 章的章节标题与核心事件描述 | ❌ 第一卷细纲缺失或内容不足，请先在 `00-大纲细纲/分卷细纲/` 中创建第一卷细纲（至少 5 章规划） |

#### 3.6.2 拦截话术

```
🛑 骨架未完成，请先补全以下内容：

<逐项列出未通过的检查项及具体缺失内容>

💡 提示：骨架不全的写作会导致后期反复修改。补全以上内容后说「开始写第 1 章」。
```

#### 3.6.3 检查时机

- 用户说「开始写第 1 章」「写第一章」「开写」等触发 novel-main 前置检查时
- 此时必须执行本检查，通过后才进入 novel-main 的 7 步循环
- 如果用户说「跳过骨架检查」，**不允许跳过**。提示：「骨架是质量的底线，不能跳过。请先补全。」

## 多书管理

### 查看所有书籍

当用户说「我有哪些书」「小说列表」时：
1. 列出 `~/novels/books/` 下所有子目录
2. 读取每个目录下 `02-设定文档/故事线状态.md`，提取进度
3. 输出：
```markdown
### 📚 我的书架

| # | 书名 | 类型 | 进度 | 最近更新 |
|---|------|------|------|---------|
| 1 | XXX  | 都市 | 12章 | 3天前   |
| 2 | YYY  | 玄幻 | 0章  | —       |

当前活跃：《XXX》
```

### 切换活跃书

当用户说「切换到《XXX》」「写《XXX》」时：
1. 确认 `~/novels/books/<XXX>/` 目录存在
2. 更新 `~/.hermes/skills/novel/_state/current_book.txt` 为 `<XXX>`
3. 输出：
```markdown
🔖 已切换到《XXX》
📊 当前进度：第 Y 章（共 Z 章大纲）
```

### 删除书籍

当用户说「删除《XXX》」时：
1. 二次确认：「确认删除《XXX》？这将永久删除所有章节和设定。(y/N)」
2. 确认后：`rm -rf ~/novels/books/<XXX>/`
3. 删除进度文件：`rm ~/.hermes/skills/novel/_state/<XXX>_progress.json`
4. 如果是当前活跃书：清除 `current_book.txt`
5. 输出：`🗑️ 《XXX》已删除`

## 错误处理

| 场景 | 处理 |
|------|------|
| 书名已存在 | 提示「《XXX》已存在」，询问：覆盖 / 换名 / 继续写入 |
| 目录创建失败 | 检查权限，建议用户手工创建 |
| 文件名含特殊字符 | 自动替换：`《》` → 移除，`：` → `-`，`/` → `_` |
| 用户中途放弃 | 不创建目录，不写任何文件 |

---

## 注意事项

- 引导式对话：一次一问，根据回答自然推进，不要审问式连问
- 宽容输入：用户提供的信息不完整时，用默认值填充 + 标注「（请填写）」
- 书名安全：自动处理文件系统不允许的字符
- 模板填充：阶段 1 收集到的信息直接填入模板，不做二次加工
- 活跃书管理：每次创建新书或切换书后，更新 current_book.txt
