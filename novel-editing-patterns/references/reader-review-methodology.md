# 读者审查方法论（深度逐章版）

> ⚠️ **特定书籍复盘文档**：以下内容来源于特定书籍的实战经验，其中的章节号、人物名、地名、数字均为该书的设定。方法论部分可通用参考，但具体数据不具有普适性。

> 来源：2026-07-27 1-30章全量逐章深度审查实践。增补了原文审查标准未覆盖的维度。

## 一、审查人设

```text
你是看了20年网文的资深读者。
从起点中文网追到番茄小说，从《斗破苍穹》《凡人修仙传》追到现在的签到流、重生流、系统流。
最近两年最爱看番茄——节奏快、爽点密、不带脑子爽。
也刷大量男频短剧（外卖小哥逆袭、赘婿打脸、重生暴富）。

现在有一本新书，你看了N章。请以读者身份给出最真实的反馈。
```

**铁律**：读者审查不是编辑审查。不是帮作者改稿。是告诉作者「这本书我读着爽不爽，哪里想划走，明天还想不想看」。不要自我审查说好话——读者花钱花时间，不说真话就是浪费作者的钱。

## 二、四维审查框架（每章必过）

### 维度1：开头吸引力

- 前300字能不能抓住人？
- 第一句有没有信息量/悬念/冲突？
- 有没有"废话开场"（天气描写/环境描写/心理活动先讲三行再进戏）？

### 维度2：弃书点排查

- 这一章有没有哪里读者想划走？
- 具体到段落：是科普太长？是对话无推进？是主角内心戏太多？是重复信息？
- 如果是「稍微有点平但半章内拉回来了」——标注为🟡，说明具体位置和拉回来的方式

### 维度3：爽点落实

- 每章至少1个实爽点（钱落地/打脸/震惊反应/收入对比/系统神秘化）
- 爽点是否自然落地？还是"爽了一半就没了"？
- 连续3章零爽点 = 沙漠段，必须标记

### 维度4：章尾钩子

- 看完这章想不想点下一章？
- 钩子的类型：悬念（对手出招）/ 承诺（明天见XX）/ 危机（冷空气/断供）/ 新信息（电话/短信/陌生人）
- 没有钩子的章节必须标注，说明为什么没钩子

## 三、全量审查维度（纯读者视角，忠实记录看完的真实感受）

### 看完每章，必须回答以下问题：

1. 这章有没有想弃（划走）的地方？有的话，具体是哪一段？（不是"还行"，是"读者为什么想弃"）
2. 这章有没有爽点？有的话，哪一点最爽？（不是"还可以"，是"具体哪个情节让读者爽了"）
3. 看完这一章，想不想看下一章？想/不想/一般，为什么？

### 全30章审查完后，必须输出汇总表：

| 统计项 | 数值 | 说明 |
|--------|------|------|
| 想弃（有划走点） | X章 | 具体是哪几章，什么原因 |
| 不想弃 | X章 | 无问题章节 |
| 看完想看下一章 | X/30章 | 每一章钩子是否有效 |
| 平均每章爽点 | X个 | 番茄节奏要求每章1-2个实爽点 |

### 终审结论（一句话）：

> 能追/不能追/要改再发。给出具体原因。

### 逻辑与连续性检查（新增维度）

> 来源：2026-07-27 用户明确要求「有没有逻辑问题、有没有坑、有没有上下剧情对不上的问题」。

### 每次全量审查必须额外检查：

1. **时间线一致性**：每章时间是否衔接？台风后几天？寒潮隔了几天？有没有时间跳跃没说清楚？
2. **人物行为一致性**：角色的能力、性格、人设是否前后一致？有没有突然变聪明/变蠢？
3. **线索闭环**：前文埋的伏笔（阿坤是内鬼/冯志强产业链/沈知予冷库圈人脉）有没有回收？有没有挖坑不填？
4. **系统设定一致性**：系统是否始终遵守初始规则（只给数据不给建议/不发任务/不主动说话）？有没有越界？
5. **数字连续性**：金钱/人口/系数/产量等数字是否前后一致？有没有前后对不上的情况？
6. **引号格式一致性**：全书对话统一使用「」成对引号。检查对话是否有用 "" 的不一致情况。patch 修改后必须确认新内容的引号格式正确。
7. **地名/实体位置一致性**：命名实体（市场/机构/地点/大楼）在不同章节中的地理位置是否一致。同一实体不能出现在两个不同城市/区域。角色当前所在位置必须能逻辑上看/听到被引用的实体（500km外看不到也听不到）。

### 逻辑检查输出格式：

```
## 逻辑验证结果

| 关键线索 | 开头埋坑位置 | 结尾闭环位置 | 验证结果 |
|----------|-------------|-------------|----------|
| X线索 | 第N章 | 第M章 | ✅ 完美闭环 |
| Y线索 | 第N章 | 未闭环 | ⚠️ 挖坑待填 |
```

## 五、评审纪律

### 诚实优先

- 不要只说好话。用户说「怎么都是好话？」＝ 你在说假话。
- 每一章必须有至少一个**真实感受**，哪怕只是「这一章平稳过渡，没有爆点但也不差」。
- 如果30章全部完美，请说明为什么——但90%的情况不可能全部完美，藏着问题不报是对用户不负责任。

### 具体优先

- 不要用「还行」「可以」「不错」这种模糊词。
- 具体到段落：哪一段开头？哪一段想划走？具体哪句对话/哪个动作让读者爽了？
- 具体到数字：字数精确到百位，评级说清楚是5星还是4星。

### 对抗「心软」的检查清单

- [ ] 我有没有因为辛苦了一晚上而放水？
- [ ] 我有没有因为前面改得太好了而放松标准？
- [ ] 我有没有因为「用户累了不想听坏消息」而选择性忽略问题？
- [ ] 我有没有把「可以接受」说成「做得很好」？
- [ ] 如果我是花了真金白银买番茄币的读者，我赌气的点在哪？
- [ ] 引号格式检查了吗？全书对话统一用「」，新增的对话有没有用成 ""？
- [ ] 人物情绪落点补全了吗？配角高光时刻有没有一句自己的收尾？

### 阅读型审查的可疑信号

以下信号说明你在「快速扫描，不是真的在阅读」：

- 每章的评价几乎一样（「节奏好」「爽点足」「没有弃点」）
- 没有引用具体段落或具体台词
- 字数统计直接从机器读取，没有"我读着觉得偏短/偏长"的主观感受
- 无法回答「这章主角做了什么」这种简单问题
- 评语套话化（「张力够」「推进自然」「合格」循环使用）

> 出现以上信号任意一条，立即停止，重新逐字阅读。

## 六、分批审查策略

### 资源控制

30章全量审查耗时长，采用以下策略控制：

1. **分批进行**：每次5-10章，逐章读完，逐章出评语。用户确认当前批次后再继续下一批。
2. **每章读一遍**，不跳读，不长篇复制粘贴原文（只引用关键段落）。
3. **每章三问**：弃点？爽点？想看下一章？——精准回答，不写废话。
4. **全量审查后**：汇总统计 + 终审结论 + 逻辑检查 + 与上一轮审查对比。

### 审查节奏

- 每章读完至出评语：2-3分钟
- 每批5章：15分钟
- 全30章：约90分钟

```
用户不要快，要准。宁慢勿快，宁缺勿滥。
```
