# 世界观对齐教训（2026-07-27）

> ⚠️ **特定书籍复盘文档**：以下内容来源于特定书籍的实战经验，其中的章节号、人物名、地名、数字均为该书的设定。方法论部分可通用参考，但具体数据不具有普适性。

> 17章完成后的全量审查。完整复盘：三层城市体系的确立、40处地名修复、opus设计模式防御。

## 根因：AI自创城市 + 跳步修复

```
模型早期把「珠江」误写为独立城市「珠河」
→ 用户说「珠河是珠江，不是城市」
→ 没有停手先完整对齐，而是跳步修了几个地方
→ 用户叫停：「不沟通清楚？反驳了解清楚？那么快速改？」
→ 最终花了一整个会话重新对齐三层城市体系
```

**核心教训**：用户说设定有问题时，第一反应不是「我马上修」，而是「停。先把设定对清楚。」对齐后再一把改完。

## 全量审查流程

1. 子 agent 审查全部章节+设定文档（传入完整白名单和禁止规则）
2. 主 Agent 逐条核验，区分真实违规和误报
3. 确定性修改用 sed 批量替换
4. 分轮修复：🔴正文违规 → 🟡设定文档 → 大纲/分卷细纲
5. 子 agent 可能误报白名单地名，需人工二次确认

## opus 设计模式防御

opus 收到写作 prompt 后，有时不直接写正文，而是先输出「设计方案」再问「需要确认两个问题」。

**防御**：prompt 首行必须以「直接输出第X章正文。不要先设计方案。不要问问题。直接写。」开头。如仍返回方案，重写 prompt 再派发。

## 粤语词 vs 北京方言

opus 有时把北京方言（如「一水儿」）误用作粤语。审查时必须对照 22 词粤语白名单验证。

## 别用「珠三角」

「珠三角」是真实地理概念（珠江三角洲）。架空世界使用「珠河三角洲」。在全部大纲/分卷细纲/人物卡中已批量替换。
