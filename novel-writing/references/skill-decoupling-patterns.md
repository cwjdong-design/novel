# 技能解耦方法论：从实例绑定到通用框架

> 来源：2026-08-01 小说创作系统（14个技能、60+文件、616KB→596KB）通用化解耦实践。

## 问题识别

技能在迭代中会自然积累实例特定数据——人物名、地名、数字、路径、平台 ID。这些数据让技能"只服务于一个项目"，无法复用或分享。

### 症状清单

- 方法论中混入特定项目的人物/地名/实体名
- 审查规则中嵌入特定项目的数值公式
- 扫描脚本中写死了白名单/黑名单值
- 创作指导绑定了特定作者的偏好（方言/风格）
- 工具脚本中写死了绝对路径和平台账户 ID

## 解耦铁律

**技能文件只包含通用方法论和流程规范。实例特定数据放在实例自己的数据目录中。**

```
技能文件（通用）              实例数据（特定）
~/.hermes/skills/<name>/     ~/projects/<instance>/
├── 方法论                     ├── 配置文件 ← 技能从这里读取规则
├── 流程规范                   │   ├── 白名单/黑名单
├── 工具脚本（参数化）          │   ├── 字段定义
└── 模板                       │   └── 风格偏好
                              └── 实际数据
```

## 5步解耦法

### 第1步：全量扫描
```bash
grep -rn '<人物名>\|<地名>\|<特定数字>' --include='*.md' <技能目录>/
```
排除目录：`_state/`、`references/`（已有标注的复盘文档）、平台特定工具。

### 第2步：分类——保留 vs 移除

| 类别 | 处理 | 示例 |
|------|------|------|
| 通用方法论 | **保留** | 流程框架、审查清单、评分体系 |
| 通用工具 | **保留+参数化** | 备份脚本、统计脚本 |
| 特定设定 | **移除或占位符化** | 世界观地名、人物状态、面板字段 |
| 特定复盘经验 | **保留但加标注** | "特定项目复盘文档"标签 |
| 平台账户数据 | **参数化** | ID、绝对路径 |

### 第3步：引入配置机制

在实例数据目录中创建配置文件（如 `书配置.md`、`project.config.json`），技能从中读取。

技能文件中引用配置：
```
"从配置文件的白名单字段读取"
"基数 × 系数 × 比例（具体值见配置）"
```

### 第4步：批量修改

大型系统（10+文件）使用 delegate_task 并行处理：
- 按文件大小和复杂度分组（每组 2-3 个文件）
- 给明确的移除清单和保留清单
- 完成后统一 grep 验证

### 第5步：零残留验证
```bash
grep -rn '<人物名>\|<地名>\|<特定数字>' --include='*.md' <技能目录>/ | wc -l
# 期望：0
```

## 特殊情况

### 复盘文档（references/）
方法论有参考价值但数据是特定的 → **加标注，不改内容**：
```markdown
> ⚠️ **特定项目复盘文档**：方法论可通用参考，具体数据不具有普适性。
```

### 工具脚本（scripts/）
- 路径硬编码 → `os.path.expanduser("~/...")` 或 `$HOME`
- 数据硬编码 → 从外部 JSON/YAML 配置读取

### 平台发布工具
ID/账户数据 → 命令行参数或环境变量，`config/` 放模板文件

## 实战数据（小说创作系统，2026-08-01）

| 维度 | 改造前 | 改造后 |
|------|--------|--------|
| 技能文件数 | 60 | 60 |
| 系统大小 | 616KB | 596KB (-3.2%) |
| 人物名残留 | 50+处 | 0 |
| 地名残留 | 30+处 | 0 |
| 特定数字残留 | 20+处 | 0 |
| 方言硬编码 | 22词固定词表 | 通用框架（从配置读取） |
| 面板字段硬编码 | 5个固定字段 | 通用占位符 |
| grep 验证 | — | 0/0/0/0 |

## 关键洞察

1. **技能膨胀是渐进的**——每次"加一个特定项目的规则"都在积累技术债。定期审计（grep 扫描）是必要的。

2. **配置外置化是核心手段**——不是删除特定数据，而是把它移到正确的位置（实例数据目录 vs 技能文件）。

3. **复盘文档加标注而非删除**——实战经验有价值，但需要明确标注"此数据来自特定项目"。

4. **delegate_task 并行处理大型解耦**——14个文件分3组并行修改，耗时3分钟而非30分钟。

5. **grep 验证不可跳过**——修改完成后必须零残留验证，子任务的输出可能有遗漏。
