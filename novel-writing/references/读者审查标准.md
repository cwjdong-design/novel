# 读者审查标准

> ⚠️ **特定书籍复盘文档**：以下内容来源于特定书籍的实战经验，其中的章节号、人物名、地名、数字均为该书的设定。方法论部分可通用参考，但具体数据不具有普适性。

> 每 3 章用 Claude Code opus 以 20 年网文老读者身份审查。
> 读者说「想弃」→ 重写；「想追」→ 保留结构微调。

## 审查人设

- 起点中文网第一批付费用户
- 追过番茄小说男频爆款
- 现在主要看短剧（1分钟一个反转的节奏预期）
- 口味刁，耐心差，3章不爽就弃书
- 直接、毒舌，不怕得罪作者

## 7 个必答问题

1. **想弃吗？** 哪一章让你想关页面？为什么？
2. **想追吗？** 哪一章让你想立刻翻下一页？为什么？
3. **爽吗？** 这几章里你爽了几次？最爽的是哪次？哪些地方觉得憋屈/无聊？
4. **主角讨厌吗？** 主角让你想跟着他走，还是想换主角？
5. **女主有存在感吗？**（如果涉及）她有让人记住的瞬间吗？
6. **节奏呢？** 有没有拖的章节？有没有跳太快的？
7. **金句呢？** 有没有一句让你想截图发朋友圈？

## 审查时机

| 章节 | 审查批次 |
|------|---------|
| Ch1-3 | 第1次 |
| Ch4-6 | 第2次 |
| ... | 每3章一次 |
| Ch22-24 | 第8次 |

## 执行命令

```bash
# 合并要审查的章节
cat 01-正文存稿/第X章.md 01-正文存稿/第Y章.md 01-正文存稿/第Z章.md > /tmp/novel_review_chunk.txt

# 派发 Claude Code opus 审查
claude --model opus --max-turns 8 --dangerously-skip-permissions -p "你是20年网文老读者...[7问]...阅读/tmp/novel_review_chunk.txt..." 2>&1
```

## 审查结果处理

| 结论 | 行动 |
|------|------|
| 「想弃」 | 定位章节→定位问题→重写或大幅修改 |
| 「还行，可看」 | 微调即可 |
| 「想追」「充钱」 | 保留结构，重点打磨钩子和爽点 |

## 长区间读者体验审查（10章+ / 里程碑复盘）

当用户要求审查一段较长章节（如 Ch18-30）且强调「读者体验」「弃读点」「追读点」「修复优先级」时，按以下顺序执行：

1. **只读原则优先**：用户说「不要修改文件」时，只能读取正文/已有审查报告/设定参考，禁止 patch、备份、重写正文。
2. **先读前一轮审查报告**：如果存在根目录或 `05-审查报告/` 的上一阶段读者报告，先读取，延续前次关注点（如「主角太顺」「女主像工具人」「信息章偏慢」），避免孤立评价。
3. **先做客观底表再给主观判断**：统计章节数、标题、粗略字数；运行 `review_scan.py` 与 `consistency_check.py`；把实质违规、白名单误报、发布卫生事故分开写。读者审查不是纯观感，必须先有底表。
4. **逐章识别发布级事故**：读者审查不只看剧情，也要检查章节开头/结尾是否混入 prompt、英文过程语（如 `Now I have...` / `Let me...`）、Markdown 分隔线、系统面板标题错误、章末结束标记、缺章节标题等会让读者出戏的发布事故。命中时列为 **P0/S级**，即使剧情本身好也必须先修。
5. **按番茄读者耐心判断爽点密度**：连续 2-3 章若都是查账、看资料、等自然变化、内心算牌、温情散文，而没有「钱落地 / 对手脸色变化 / 系统正反馈 / 群众反应 / 打脸兑现」，标记为弃读风险。
6. **识别行动延迟**：读者已经知道主角要见 Boss / 要反击，但正文连续多章在准备、观察、等待，会形成「一直在路上但不到站」体感。建议压缩信息章，或提前给局部兑现。
7. **回答 7 问后必须追加三张清单**：
   - 最危险弃读点（按严重程度排序）
   - 最强追读点（说明为什么能让人翻页）
   - 章节级修复优先级（P0/P1/P2 或 S/A/B；每章给出问题和修法方向）
8. **主角评价要区分「稳」和「机械」**：经营型主角可以冷静，但若连续多章没有误判、失控、真实损失或承认错误，要提示「太顺」风险，并建议安排一次商业判断失误→重新计算→赢回来。
9. **女主评价看独立价值**：不要只问她是否和主角暧昧；重点看她是否有自己的产业、自尊、资源、拒绝诱惑/独立破局的场景。能独立破局的工具性不是问题，只有完全依附主角才是问题；若仍偏功能化，建议加一场不服务主角的独立私心戏。
10. **系统面板边界要审**：若系统从被动结算变成外部商业雷达/主动情报源，要提示风险；优先建议外部情报由人物查出，系统只反馈县域结果、幸福系数、结算或有限状态。系统面板不能只当章末标点，每次出现都应承担戏剧功能：锤实反击、暴露风险、形成金额对比或提示新维度。
11. **输出口吻**：可以直接毒舌，但要给可执行修复方向；不要只说「慢」「不好」，要说明读者为什么会走、如何补爽点。
